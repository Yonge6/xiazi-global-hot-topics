# 虾子曰每日自动化运行手册

## 上游与时间表

- ChatGPT 上游任务：`https://chatgpt.com/share/6a59a9b3-0430-83ea-b58c-2c0b99903e86`
- ChatGPT 计划时间：每天北京时间 05:00。
- Codex 轮询：05:05、05:20、05:35、05:50。
- Codex 最终门：06:00。

ChatGPT 共享页可能是滞后的只读快照，所以每次检查必须以“当天日期、生成时间、完整 9 条文字、完整 18 张海报”为准，不得因为页面可打开、显示“正在生成”或媒体总数看似足够就认定已完成。共享页只用于定位和初步监控；如果共享页未更新、长时间停在生成态或与用户截图不一致，必须转到用户已登录的原始 `chatgpt.com/c/...` 会话，只读刷新原始会话并重新打开媒体查看器后再判定。不得因为刷新而重发提示词。

如果用户在当天另行提供新的 ChatGPT 共享链接，优先把它作为本次运行的上游入口，并记录到当天监控 JSON；它只是当日覆盖项，除非用户明确说明已更换长期任务，否则不得覆盖上面的固定共享链接。

## ChatGPT 出图执行顺序（每日固定）

1. 由 ChatGPT 上游任务接收当天完整 SOP：固定 9 槽位、事实核验、两张官方 IP 母版、当天 Style Atlas 风格、9:18 独立成品、所有中英文文字直接存在于最终像素。
2. 先逐张生成中文 NO.01–NO.09；不得一次输出九宫格、拼图或仅背景。每张完成后保留独立原图。
3. 仅在中文 9 张全部完成且可验收后，再逐张生成英文 NO.01–NO.09；英文必须与对应中文编号、主题、构图骨架和角色逻辑一一对应。
4. Codex 每次只读检查生成状态；若仍在生成则等待后复查，不打断、不重发、不混入新的提示词。
5. 若“正在生成”长时间无新增海报，按固定顺序排查：先刷新原始登录会话，再重新打开媒体查看器，再按日期、语言和 NO.01–NO.09 清点；共享页刷新仍是旧快照不能作为失败证据。
6. 只有中英各 9 张均完成且通过接收门，才下载、压缩、发布。只有 ChatGPT 明确失败、超过当日发布窗口或输出无法修复时，才进入 Codex Image2 兜底；不得用未完成的中文组替代完整双语刊。

## ChatGPT 原图接收与清点

1. 来源优先级固定为：已登录的原始 `chatgpt.com/c/...` 会话及其媒体查看器 > 当天共享页 > 用户截图。共享页和截图可证明“可能已经生成”，但最终仍需在原始会话中定位并下载原图。
2. 长时间没有新结果时，不得直接判定生成失败：记录当前状态，刷新原始会话，重新进入媒体查看器，再检查一次当天素材。若用户指出“这里有”或提供成品截图，必须先在原始会话媒体库中继续查找，找到前不得抢先启动 Image2 替代。
3. 不得用媒体总数推断完成度。媒体库可能同时包含两张 IP 母版、作废九宫格、旧日期海报、失败草稿和当天成品；必须逐张按 `日期 + 语言 + NO.编号` 建立接收清单。
4. 只接收当天中文 NO.01–NO.09 与英文 NO.01–NO.09 共 18 张独立原图。明确排除：IP 母版、九宫格/拼图、旧日期图片、只有背景的版本、被用户否决的草稿、语言或编号不明的图片。
5. 从原始会话使用下载按钮取得原图，不得以聊天截图、页面截图或浏览器缩略图代替。下载后记录来源会话、媒体位置、语言、NO.编号、日期、文件尺寸和 SHA-256，保存到 `tmp/daily-upstream-monitor/YYYY-MM-DD-receipt.json`。
6. 接收清单必须恰好 18 项且编号无缺失、无重复；发现某一张“缺失”时，先复查媒体查看器和原始会话，不得用旧九宫格补位。只有确认原始会话确实没有该图，才为这一张启动合规兜底。
7. 下载完成只代表“素材已接收”，不代表任务完成；同一次运行必须继续完成压缩、入库、构建、部署和生产验收，不得以“已找到”“已下载”或“正在部署”结束。

## 防重入与早退

1. 每次运行先查 `https://xiazishuo.com/api/content/`。
2. 如果 `issueDate` 已是北京时间当天且生产验收通过，立即退出。
3. 使用 `tmp/daily-upstream-monitor/YYYY-MM-DD.lock` 作为独占锁；另一次运行正在处理时不得并发发布。
4. 将每次检查的时间、页面日期、文字数、图片数和判定写入 `tmp/daily-upstream-monitor/YYYY-MM-DD.json`。

## ChatGPT 结果接收门

以下项目必须全部满足：

- 日期为北京时间当天，不得复用昨日结果。
- 正好 9 条：NO.01 总览、NO.02 世界杯、NO.03 AI、NO.04 OPC、NO.05–NO.09 其他热点。
- NO.01 只概括后面 8 条，不得有第 10 个事件。
- 中英文事实一致，来源可访问，高风险事实有官方或交叉来源。
- 9 张中文 PNG 与 9 张英文 PNG 均为独立 9:18 成品。
- 中英文按 NO.01–NO.09 一一匹配，版式骨架、主风格、配色和角色位置逻辑一致。
- 虾子曰与豆豆龙与权威母版一致，不改脸、物种、主色或核心服饰。
- 文字可读，无乱码、错字、缺字、占位文字或错误网址。

## 每日视觉风格选择

1. 每天开始规划海报前，以北京时间当天打开 `https://style-atlas.wonderelian.com/`，读取首页“今日推荐”当前激活的风格卡；不得沿用昨日风格或把相邻卡片误当成今日推荐。
2. 将当天风格的编号、中英文名称、源图 URL、读取时间和是否启用兜底写入 `tmp/daily-fallback-YYYY-MM-DD/style-selection.json`，并保存源图作为 Image2 的视觉参考。
3. 当日 9 张中文与对应 9 张英文统一使用该风格的构图语言、材质、色彩和装饰语汇；各主题可变化场景，但中英文同编号必须保持同一视觉骨架。
4. 风格站只决定“每日变化的视觉表达”，不得覆盖以下固定门槛：往期精品海报的信息层级和叙事密度、9:18 独立完整 PNG、全部文字直接存在于最终像素、虾子曰与豆豆龙权威母版身份、日期与网址、编号和中英文事实对应。
5. 不机械复制或挪用特定文化的神圣符号、文字、徽记或仪式物件；只提取可公开使用的色彩、材质、几何节奏和一般性构图特征。
6. 风格站连续两次无法访问或当日推荐无法判定时，记录故障并回退到 `docs/sop/虾子曰全球热点海报-阳光高端版视觉总规范.pdf`，不得因此阻塞 06:00 兜底发布。

## 压缩与发布

1. 优先 TinyPNG；登录、付费、CAPTCHA 或下载失败时改用 Sharp。
2. 保持原像素尺寸和 PNG 格式，不生成缩略图。
3. 写入数据前先校验 `category` 只能是生产 schema 允许的 `international`、`technology`、`business`、`science`、`climate`、`culture`、`sports`；`economy`、`health` 等展示词必须映射到允许值，禁止等部署后再靠 HTTP 500 发现。
4. 同步 current issue、同日 archive、Story Pool、18 张当前海报与 18 张当日归档海报。
5. 发布前运行数据校验、项目检查和生产构建；任一失败先修复，不得上传半成品。
6. 只允许更新 `Yonge6/xiazi-global-hot-topics` 和 Vercel `xiazishuo`；不触碰 VileSaint。
7. 网站先于微信草稿，第三方服务不得阻塞网站。

## 06:00 兜底

06:00 仍未通过 ChatGPT 结果接收门时：

1. 按 `docs/sop/虾子曰每日全球热点固定规则.pdf` 联网核验 50–100 条候选并完成当天 9 条双语内容。
2. 按 `docs/sop/虾子曰全球热点海报-阳光高端版视觉总规范.pdf` 生成或补齐 18 张海报。
3. 兜底生图只能使用 Codex 内置 GPT Image 2/image2。不得改用 Gemini、DALL-E、本地 SVG 模板、程序叠字或背景板。
4. 必须把两张固定 IP 母版作为图像参考：
   - `public/brand/characters/xiazi/xiazi-master-front.png`
   - `public/brand/characters/doudou/doudou-master-front.png`
5. 中文 9 张统一规划后逐张生成，英文 9 张对应翻版；全部是最终像素成品，不留后期占位。
6. Image2 提示词优先使用“当天风格 + 必需场景 + 两张角色母版 + 全部最终原文”的最短完整结构；删除重复风格描述和重复禁止项可以降低超时风险，但不得删减任何最终文字区块、9:18 比例或固定 IP 身份要求。
7. 更换 Codex 编排模型（例如 GPT-5.6 改为 GPT-5.5）不等于更换 Image2，也不能作为 Image2 返回正常的证据；必须以实际 PNG 负载落盘为准。长时间无图片时使用有界超时并记录，不得无限等待或宣称成功。
